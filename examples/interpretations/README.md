# Примеры интерпретаций

Каждый `.yaml` — готовая интерпретация. Загрузить через
`/interpretations` → вкладка **YAML** → вставить содержимое → **Добавить**.

| Файл | Демонстрирует | На каких PCAP работает |
|---|---|---|
| `01_fixed_magic.yaml` | Простой fixed-framing | любой TCP с кратными 13 байтами сообщениями |
| `02_length_prefix.yaml` | Length-prefix: размер из поля | протоколы вида «2 байта длины + payload» |
| `03_delimiter.yaml` | Разделитель CRLF | текстовые протоколы (HTTP-подобные, SMTP) |
| `04_expression.yaml` | Вычисляемые поля + constraints | датчики: сырое значение → температура |
| `05_corpus.yaml` | Критерии корпуса для verify | любой |

## Импорт через CLI

```bash
taptuna interp-add --project ./myproj --file 04_expression.yaml
taptuna corpus-add --project ./myproj --name c1 --file 05_corpus.yaml
```

## Что показывают примеры

### 01 — Базовый fixed-framing

Простое разбиение потока на блоки фиксированной длины. Одно поле
`raw: bytes`. Хорошо для понимания базового синтаксиса.

### 02 — Length-prefix

Демонстрирует **зависимость размера от другого поля**:
`size: {from_field: len}`. Это самый частый паттерн в бинарных
протоколах: 2 байта длины + payload переменной длины.

### 03 — Delimiter

Разбиение по `\r\n` — как в текстовых протоколах. `include_delim:
false` означает, что разделитель не входит в тело сообщения.

### 04 — Expression и constraints

Два ключевых механизма:

1. **Expression-поля** — вычисляются из других полей:
   `temp = temp_raw // 10`. `temp_raw` извлекается из байтов,
   `temp` — уже результат вычисления.
2. **Constraints** — проверяются при verify. `-40 <= temp <= 85` —
   диапазон физически допустимых значений. Если выйдет за границы,
   сообщение получит статус `violation`.

### 05 — Корпус

Критерии отбора сессий для verify: сессии с портом 8080 и хотя бы
одним пакетом. Можно комбинировать `any_ports`, `min_packets`,
`min_bytes`, `has_syn`, `directions`, `captures`.
