# Демонстрация: полный исследовательский сценарий

Сценарий защиты проекта. Показывает, как инструмент
помогает получить и проверить знания об обмене и передать исследование
другому инженеру.

## Подготовка (за 5 минут до демонстрации)

```bash
cd /path/to/Taptuna_my
source .venv/bin/activate

# 1. Сгенерировать эталонный PCAP
rm -rf examples/demo_project
python examples/generate_demo.py

# 2. Запустить сервер
taptuna serve --project examples/demo_project --port 5000
```

Открыть `http://127.0.0.1:5000/`.

**Дополнительно создайте две интерпретации** через `/interpretations`
(понадобятся в шагах 6 и 7):

```yaml
name: strict_13
kind: declarative
framing: {kind: fixed, size: 13, max_message: 1024}
fields:
  name: message
  fields:
    - {name: raw, type: bytes, offset: 0, size: 13}
constraints:
  - op: eq
    a: {op: field, name: raw}
    b: {op: const, value: "WRONG"}
semantics: {}
```

```yaml
name: partial_20
kind: declarative
framing: {kind: fixed, size: 20, max_message: 1024}
fields:
  name: message
  fields:
    - {name: raw, type: bytes, offset: 0, size: 20}
constraints: []
semantics: {}
```

## Шаг 1. Импорт записи (2 мин)

**Экран:** Главная.

**Действия:**
1. Перетащить `examples/input/test.pcap` в dropzone.
2. Дождаться завершения (панель задач внизу справа покажет SSE-прогресс).

**Что показываем:**
- Один вызов tshark на файл (правило §6.2).
- sha256 копии, размер, число пакетов — provenance.
- В таблице Captures появилась запись.

**Сообщение:** «Источник неизменён: файл скопирован под sha256, повторный
импорт того же файла даст явное предупреждение».

## Шаг 2. Обзор сессий (2 мин)

**Экран:** Сессии.

**Действия:**
1. Показать таблицу: 5-tuple, число пакетов в направлениях, признак SYN.
2. Фильтр по IP/порту, сортировка по столбцу «Байты».
3. Клик на #1 → переход на карточку сессии.

**Сообщение:** «Здесь видно структуру обмена: кто с кем, сколько пакетов и байт в каждом направлении. Колонка SYN — это признак roles_established: был ли в потоке SYN без ACK, установлены ли роли сторон. FIN в этой таблице не показывается — его видно в карточке сессии на уровне пакетов (flags в таблице пакетов)».

## Шаг 3. Исследование потока (3 мин)

**Экран:** Карточка сессии (`/sessions/1`).

**Действия:**
1. Переключить направление `a_to_b` / `b_to_a`.
2. Показать hex-viewer с подсветкой gaps и ambiguities.
3. Прокрутить в середину потока → показать виртуальный скролл.
4. **Кликнуть по байту `48` (offset 0)** → popup:
   - offset, frame, seq, len, flags.
   - Кнопка «Показать в пакетах» → подсветка строки.
5. Клик по Offset в таблице пакетов → прыжок в hex-viewer.

**Сообщение:** «Клик по байту — переход к пакету источника. Виртуальный
скролл работает для потоков > 1 МиБ».

## Шаг 4. Исследование: framing-tool и применение (5 мин)

**Экран:** Исследование.

**Действия:**

1. Выбрать сессию #1 (появится после выбора в селекте).

2. **Framing-tool — стратегия `fixed`, size=13** → «Применить».
   - 1 сообщение, 13 байт, leftover=0.
   - Клик «к байтам» → hex-viewer прыгает к offset 0.

3. **Стратегия `delimiter`, delim=`2c20` (", ")** → «Применить».
   - 1 сообщение `Hello` (5Б), leftover 6Б (`World!`).
   - Оранжевый индикатор leftover + ссылка «перейти к хвосту».

4. **Стратегия `length_prefix`, prefix_bytes=2, max=1024** → «Применить».
   - framing_error: «message exceeds max_message (18535)».
   - Движок честно отвергает неверную гипотезу.

5. **Стратегия `regex`, pattern=`[A-Z][a-z]+`** → «Применить».
   - 2 сообщения: `Hello`, `World`.
   - Клик «Экспорт JSON» → скачивается файл с границами.

6. **Панель «Применить интерпретацию к текущей сессии»**:
   - Выбрать `demo_fixed13@v1`, direction `a_to_b` → «Применить».
   - Сводка: `Сообщений: 1 · ok 1`.
   - Клик «к байтам» → прыжок в hex.

7. **Панель «Гипотезы и наблюдения»**:
   - Добавить гипотезу: «Первое поле — magic, всегда 0x48», статус `open`.
   - Добавить наблюдение: «В ответ на send_data приходит 13 байт», offset `0`.
   - Таблица гипотез обновляется.

8. **Панель «Сравнить с другой сессией»** (если в проекте больше 1 сессии):
   - Выбрать вторую сессию → «Сравнить».
   - Показать таблицу: 5-tuple, размеры, общий префикс/суффикс.
   - Чекбокс «Синхронизировать скролл».

**Сообщение:** «Граница TCP-пакета не определяет границу сообщения.
Подбираем framing на потоке, применяем интерпретации, фиксируем гипотезы —
всё в одном месте».

## Шаг 5. Верификация: полный цикл (4 мин)

**Экран:** Проверка.

**Действия:**

1. **Прогон №1: ok**
   - Корпус `demo_corpus`, интерпретация `demo_fixed13@v1`, seed=0.
   - **Запустить**.
   - Результат: `verdict=ok`, `messages=1`.

2. **Прогон №2: violation (контрпример)**
   - Интерпретация `strict_13@v1`.
   - **Запустить**.
   - Результат: `verdict=violation`, `messages=1`.

3. **Прогон №3: unknown_frame (неизвестный участок)**
   - Интерпретация `partial_20@v1`.
   - **Запустить**.
   - Результат: `verdict=unknown_frame`, `messages=1`.

4. **Переход к байтам из результата:**
   - У прогона №2 → кнопка «Результаты».
   - В таблице клик по `#1` или «→ байты» → открывается
     `/sessions/1?offset=0&direction=a_to_b`.
   - Hex-viewer прокручивается к offset 0, байт подсвечивается жёлтым.

**Сообщение:** «Пять статусов: ok, violation, ambiguous, incomplete,
not_applicable, unknown_frame. Вердикт — самый тяжёлый. Из результата
можно перейти к байтам источника».

## Шаг 6. Журнал действий (2 мин)

**Экран:** Журнал.

**Действия:**
1. Импортированный журнал `demo_actions` уже есть.
2. Клик «Записи» → таблица `connect`, `send_data`, `close`.
3. Включён чекбокс «Связать с сессиями» (window=2.0).
4. Показать колонку **Сессии**: ссылки `#1`.
5. Клик по `#1` → возврат к сессии.

**Сообщение:** «Журнал фиксирует условия эксперимента. Связь с сессиями —
по временному окну. Можно вернуться от действия к байтам».

## Шаг 7. Отчёт (3 мин)

**Экран:** Отчёт.

**Действия:**

1. **Отчёт для прогона №2 (`strict_13`, violation)**
   - Выбрать run #2 → форматы MD + HTML + machine_model → **Сгенерировать**.
   - Открыть HTML.

2. **Показать разделы §11.1:**
   - §1 Цели и границы
   - §2 Метод (команда tshark, политики)
   - §3 Корпус (sha256 записей, критерии)
   - §4 Проверенные примеры (`ok`)
   - **§5 Контрпримеры** (`violation` — конкретное сообщение)
   - §6 Неизвестные участки (пусто для этого прогона)
   - §7 Область применимости
   - §8 Открытые вопросы
   - **§9 Гипотезы и наблюдения** (два блока)
   - §10 Checksum offloading

3. **Отчёт для прогона №3 (`partial_20`)**
   - Сгенерировать ещё раз → §6 «Неизвестные участки» заполнен.

4. **machine_model.json**
   - Скачать, показать структуру: `framing`, `fields`, `constraints`,
     `provenance`.
   - Это воспроизводимая модель, применимая к новым данным без TapTuna.

**Сообщение:** «Отчёт — переносимое представление исследования. Markdown —
source of truth, HTML — для чтения, machine_model.json — для повторного
применения».

## Шаг 8. Перенос проекта (1 мин)

```bash
# Скопировать проект в другой каталог
cp -r examples/demo_project /tmp/demo_moved

# Открыть из нового места
taptuna serve --project /tmp/demo_moved --port 5001
```

Открыть `http://127.0.0.1:5001/` → всё работает: captures, сессии,
интерпретации, прогоны, отчёты. В `docs/REUSE.md` — команды повторного
применения.

**Сообщение:** «Проект переносится целиком: относительные пути, sha256
источников, все интерпретации и результаты. Другой инженер открывает
и продолжает исследование».

## Шаг 9. CLI и архитектура (2 мин)

**Терминал:**

```bash
# Список всех команд
python -m taptuna.cli --help

# Список прогонов
python -m taptuna.cli runs --project examples/demo_project

# Результаты
python -m taptuna.cli results --project examples/demo_project --run 2

# Генерация отчёта из CLI
python -m taptuna.cli report --project examples/demo_project --run 2 --format md,html,json

# Rust-тесты
cd taptuna_core && cargo test 2>&1 | tail -5
cd ..

# Python-тесты
python -m pytest tests/ -q 2>&1 | tail -3
```

**Что показать:**
- 13 CLI-команд (весь workflow без UI).
- 23 Rust-теста + ~49 Python-тестов.
- Bench: reassembly 100 МиБ за 46.8 ms (требование ≤ 90 с).

**Сообщение:** «Всё воспроизводится без UI. Есть метрики: 100 МиБ за
46.8 ms — в 1900 раз быстрее требования §12.7».

5. Verify `strict_13` → run → «→ байты» (1 мин).
6. Отчёт → HTML, §5 (30 сек).
7. Перенос проекта (30 сек).
