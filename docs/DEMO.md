# Демонстрация: полный исследовательский сценарий

Сценарий защиты проекта. Показывает, как инструмент
помогает получить и проверить знания об обмене и передать исследование
другому инженеру.

## Подготовка (за 5 минут до демонстрации)

```bash
cd /path/to/Taptuna_my
source .venv/bin/activate

# 1. Сгенерировать эталонный PCAP
python -m taptuna.examples.generate

# 2. Создать рабочий проект
rm -rf /tmp/demo_project
taptuna init --project /tmp/demo_project

# 3. Запустить сервер
taptuna serve --project /tmp/demo_project --port 5000
```

Открыть `http://127.0.0.1:5000/`.

## Шаг 1. Импорт записи (2 мин)

**Экран:** Главная.

**Действия:**
1. Перетащить `taptuna_core/python/taptuna/examples/input/test.pcap` в dropzone.
2. Дождаться завершения (панель задач внизу справа покажет прогресс через SSE).

**Что показываем:**
- Один вызов tshark на файл (правило §6.2).
- sha256 копии, размер, число пакетов — provenance.
- В таблице Captures появилась запись.

**Сообщение:** «Источник неизменен: файл скопирован под sha256, повторный
импорт того же файла даст явное предупреждение».

## Шаг 2. Обзор сессий (2 мин)

**Экран:** Сессии.

**Действия:**
1. Показать таблицу: 5-tuple, число пакетов в направлениях, признак SYN.
2. Фильтр по IP/порту, сортировка по столбцу «Байты».
3. Клик на #1 → переход на карточку сессии.

**Сообщение:** «Здесь видно структуру обмена: SYN, данные, FIN. Признак
roles_established — установлены ли роли сторон по SYN».

## Шаг 3. Исследование потока (3 мин)

**Экран:** Карточка сессии (`/sessions/1`).

**Действия:**
1. Переключить направление `a_to_b` / `b_to_a`.
2. Показать hex-viewer с подсветкой gaps и ambiguities.
3. Прокрутить в середину потока → показать виртуальный скролл.
4. Клик по Offset в таблице пакетов → прыжок в hex-viewer.
5. Вернуться к `/research`, выбрать сессию 1.

**Сообщение:** «Виртуальный скролл работает для потоков > 1 МиБ.
Клик по ячейке — переход к байтам источника».

## Шаг 4. Поиск структуры через framing-tool (4 мин)

**Экран:** Исследование.

**Действия:**

1. **Стратегия `fixed`, size=13** → «Применить».
   - 1 сообщение, 13 байт, leftover=0.
   - Клик «к байтам» → hex-viewer прыгает к offset 0.

2. **Стратегия `delimiter`, delim=`2c20` (", ")** → «Применить».
   - 1 сообщение `Hello` (5Б), leftover 6Б (`World!`).
   - Оранжевый индикатор leftover + ссылка «перейти к хвосту».

3. **Стратегия `length_prefix`, prefix_bytes=2, max=1024** → «Применить».
   - framing_error: «message exceeds max_message (18535)».
   - Показываем, что движок честно отвергает неверную гипотезу.

4. **Стратегия `regex`, pattern=`[A-Z][a-z]+`** → «Применить».
   - 2 сообщения: `Hello`, `World`.

5. Клик «Экспорт JSON» → скачивается файл с границами сообщений.

**Сообщение:** «Граница TCP-пакета не определяет границу сообщения. Здесь
мы подбираем framing на потоке и видим результат мгновенно».

## Шаг 5. Формирование интерпретации (2 мин)

**Экран:** Интерпретации.

**Действия:**
1. Показать YAML-редактор.
2. Заполнить:
   ```yaml
   name: demo_fixed13
   kind: declarative
   framing: {kind: fixed, size: 13, max_message: 1024}
   fields:
     name: message
     fields:
       - {name: raw, type: bytes, offset: 0, size: 13}
   constraints: []
   semantics: {}
   ```
3. «Добавить» → появляется `demo_fixed13@v1`.
4. Клик «Применить» → выбрать сессию 1, direction a_to_b → «Применить».
5. Показать JSON с результатом.

**Сообщение:** «Интерпретация — это декларативная модель. Программно
применяется к данным, версионируется, не меняет исходные байты».

## Шаг 6. Верификация на корпусе (3 мин)

**Экран:** Проверка.

**Действия:**
1. **Новый корпус:** name=`demo_corpus`, criteria=`{"any_ports": [8080]}`.
2. **Запустить верификацию:** выбрать `demo_corpus` + `demo_fixed13@v1`, seed=0.
3. Наблюдать SSE-прогресс в панели задач.
4. Результат: verdict `ok`, 1 сообщение.
5. Клик «Результаты» → таблица с сообщением, offset, length, result_hash.
6. Создать **вторую версию** интерпретации с size=12 → verify заново.
   - Показать, что старые результаты помечены `stale`.

**Сообщение:** «Верификация автоматически прогоняет интерпретацию по
корпусу. Сводка учитывает весь набор: ok, violation, ambiguous, incomplete,
not_applicable. Изменение интерпретации не удаляет старые прогоны — они
помечаются как устаревшие».

## Шаг 7. Связь с журналом действий (2 мин)

**Экран:** Журнал.

**Действия:**
1. Импортировать `/tmp/actions_sync.yaml` (согласованные ts).
2. Клик «Записи» → таблица.
3. Показать колонку **Сессии**: ссылки `#1`.
4. Клик по `#1` → возврат к сессии.

**Сообщение:** «Журнал действий фиксирует условия эксперимента. Связь
с сессиями — по временному окну. Можно вернуться от действия к байтам».

## Шаг 8. Генерация отчёта (2 мин)

**Экран:** Отчёт.

**Действия:**
1. Выбрать run #1 → форматы MD + HTML + machine_model → «Сгенерировать».
2. Открыть HTML → показать разделы 1–10 (§11.1): цели, метод, корпус,
   проверенные примеры, контрпримеры, неизвестные участки, область
   применимости, открытые вопросы, гипотезы, checksum offloading.
3. Скачать `machine_model.json` — воспроизводимая модель.

**Сообщение:** «Отчёт — это переносимое представление исследования.
machine_model.json можно применить к новым данным без TapTuna».

## Шаг 9. Перенос проекта (1 мин)

```bash
# Скопировать проект в другой каталог
cp -r /tmp/demo_project /tmp/demo_moved

# Открыть из нового места
taptuna serve --project /tmp/demo_moved --port 5001
```

Открыть `http://127.0.0.1:5001/` → всё работает. В `docs/REUSE.md` — команды
повторного применения.

**Сообщение:** «Проект переносится целиком: относительные пути, sha256
источников, все интерпретации и результаты. Другой инженер открывает
и продолжает исследование».

## Итог

| Требование §7.1 | Что показали |
|---|---|
| R1 Работа с обменом | Шаги 1–3 |
| R2 Средства исследования | Шаги 3–4 |
| R3 Интерпретации | Шаг 5 |
| R4 Проверка | Шаг 6 |
| R5 Сохранение/перенос | Шаг 9 |
| R6 Отчёт + reuse | Шаги 8–9 |

**Что не входит в демонстрацию:**

- Реальный PCAP от устройства (в репозитории — эталонный стенд).
- Журнал действий, согласованный по времени с PCAP (генерируется на лету).
- Ошибочные предположения и их уточнение (можно показать на шаге 4 через
  `length_prefix`, но полный цикл «гипотеза → контрпример → уточнение»
  требует отдельного сценария).

## Быстрый сценарий (5 минут) для ограниченного времени

1. Импорт → Сессии → Карточка #1 (30 сек).
2. Framing-tool: fixed 13 → 1 сообщение; delimiter → 2 (2 мин).
3. Добавить интерпретацию → verify → verdict ok (2 мин).
4. Отчёт → HTML (30 сек).
