Гипотезы и наблюдения

📖 Как работать с гипотезами

Что такое гипотеза? Это предположение о смысле или структуре данных, которое можно проверить на всех сообщениях корпуса автоматически. Гипотеза не меняет байты и не влияет на статусы verify — она живёт отдельно и помогает отделить «правила разбора» от «предположений о смысле».

Порядок работы — обязателен именно такой:

  1. Создайте интерпретацию (вкладка «Интерпретации»).
    Она описывает: как разбить поток на сообщения (framing) и какие поля извлечь из каждого сообщения (fields).
    Пример: framing fixed size=13, поля magic: u8, len: u16be, payload: bytes.
  2. Запустите verify (вкладка «Проверка»).
    Verify прогоняет интерпретацию по корпусу сессий и сохраняет значения полей для каждого сообщения в БД. Без этого шага гипотезу проверить не на чем — нет данных.
  3. Создайте гипотезу (эта страница).
    Укажите:
    • Формулировку — что именно вы предполагаете, словами: «magic всегда 0x48», «длина не превышает 1024».
    • Выражение — проверяемое условие над полями из интерпретации: magic == 0x48, len(payload) <= 1024.
    • Интерпретацию — чьи поля использовать. Обязательно ту, что уже прогнана через verify.
  4. Нажмите «Проверить».
    Выражение вычислится для каждого сообщения. Результат: satisfied — истина, violated — ложь, not_applicable — поле не извлекалось в этом сообщении, error — ошибка вычисления (деление на ноль, переполнение).
  5. Смотрите «Результаты».
    Каждый violated — это контрпример с указанием сообщения и ссылкой «→ байты»: сразу видно, на каких байтах гипотеза не выполнилась. Авто-статус гипотезы:
    • supported — есть satisfied, нет violated;
    • refuted — есть хотя бы один violated;
    • inconclusive — нет ни satisfied, ни violated (проверка ничего не дала).

Примеры типовых гипотез для сетевого трафика:

Что проверяемФормулировкаВыражение
Фиксированный заголовок «Первый байт всегда 0x48» magic == 0x48
Границы длины «Длина сообщения от 4 до 512» 4 <= len <= 512
Наличие поля «Payload присутствует всегда» exists(payload)
Согласованность полей «len == фактической длине payload» len == len(payload)
Диапазон значения «Температура в [-20, 20]» -20 <= temp and temp <= 20
Известный набор «opcode 0x01, 0x02 или 0x03» opcode == 1 or opcode == 2 or opcode == 3

Важно: успешная проверка структуры (framing + fields) не подтверждает смысловую гипотезу. Совпадение на конкретном корпусе — это повод для более широкой проверки, а не доказательство назначения поля. Смотрите раздел «Основания» в результатах — какие наблюдения привели к гипотезе.
